# 代码整理与构建发布检查

日期：2026-11-13。范围：A1/CM5 主板交互导览、博客分类页，以及支撑这两部分的构建发布流程。

## 结论

两部分已整理为可复用的组件与数据配置，交接入口为 [文档站可复用 UI 标准 v1.0](../standards/site-ui/README.md)。当前本地生产构建未发现阻塞问题，完整检查命令 `npm run check` 已通过。

本报告记录发布前的代码整理与本地验证。GitHub Actions 的 Ubuntu 构建、服务器上传与 Pages 发布结果，以对应提交的 [自动发布工作流](https://github.com/dshanpi/Docs/actions/workflows/deploy.yml) 为准。

| 原问题 | 改动 |
| --- | --- |

| A1 的普通产品页需要复制整段交互代码 | A1 入口现在只向通用 BoardExplorer 传入名称、文案和板型数据；标注数量自动计算 |
| 主板数据错误在运行后才暴露 | 校验重复 ID、未知面、默认接口和超出裁切范围的热点；页面 SSR 构建时同步验证 |
| 博客业务配置与索引算法混写 | 分类、系列、兼容规则移入 `plugins/blog-catalog/config.cjs`，索引逻辑保留在 `catalog.cjs` |

| 桌面环境文档的 3 处锚点失效 | 修正为现有标题 ID，并把 `onBrokenAnchors` 设置为 `throw` |
| 发布前缺少 PR 检查，依赖安装不锁定 | CI 改用 `npm ci`；PR 只检查，master 的验证产物用于两个现有发布目标 |
| 构建任务拥有发布写权限，可能交错部署 | 构建、Pages 发布、服务器同步拆成独立任务，写权限仅给 Pages 发布，同一分支的工作流串行执行 |
| SSH 全量上传耗时过长，阻塞主站发布 | 两个发布任务仅依赖构建，使用同一份已验证产物并行执行；Pages 不等待 SSH |

没有升级框架或依赖版本。主板照片、接口坐标、技术内容、文章地址和已确认的博客视觉方案保持原有语义；博客装饰右箭头仍全部移除。

## 发布边界与交接事项

- 发布提交需包含组件、插件、图片、教程、测试与脚本等完整功能文件，不能只提交原有文件的 diff。
- 现有目标保持不变：SSH 目录 `/www/wwwroot/rockchip.100ask.net/`，以及 GitHub Pages 的 `gh-pages` / `wiki.dshanpi.org`。
- 2026-11-13 发布排查：主站 DNS 指向 GitHub Pages；约 774 MiB 的产物通过 SSH 全量传输，历史成功上传耗时约 76 分钟。已解除两处发布的前后依赖，但服务器全量上传速度仍受网络影响。
- HOST、USERNAME、PASSWORD、PORT Secrets 的实际值与可用性未读取或验证；Pages 配置和线上 DNS 也未更改。
- SSH 仍采用覆盖复制，旧文件不会自动清理，上传不是原子切换；两处发布不是同一个事务。若需要目录切换或自动清理，应先核对服务器结构，再另行实施。
- 新增主板组件文案主要为中文，部分新教程的英文路由使用 Docusaurus 默认语言回退。构建通过不等于翻译已经完成。
- 本次验证是网页与发布准备检查，不包括开发板实际刷机、接口电气参数或外设兼容性验证。

后续维护从 `npm run check` 开始；组件数据和接入方式按 [统一标准](../standards/site-ui/README.md) 执行。
